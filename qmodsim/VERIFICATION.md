# Verification of the seven Tagak Café models

**25 November 2026.** These standalone scenarios use fixed inputs. The POS lab also reads branch-scoped operational aggregates. The scenarios illustrate decisions; their results do not establish measured campus demand, financial loss or production uptime.

| Model and purpose | Calculation, assumptions and result | Application relationship |
| --- | --- | --- |
| Arrival intensity and preparation | At hour t, λ(t)=8+Σ A exp(−(t−b)²/(2s²)) orders/hour. Break centers b=(10,12,15), amplitudes A=(22,28,20), s=0.55 hours. Noon gives 36.030/hour. Baseline exponential mean is 60/8=7.5 minutes. Gamma mean is 4×0.65=2.6 minutes. Lognormal mean is exp(1.15+0.42²/2). | Compare hourly arrivals with modeled peaks. The script evaluates intensity and means; it does not fit arrivals or service distributions to observed orders. |
| Finite-capacity queue | Poisson arrivals λ=28/hour, two identical exponential servers c=2, μ=14/hour each, total capacity K=10. State weights start at 1 and multiply by λ/(min(n,c)μ) for n=1…K; normalize. P₀=1/21, P₁₀=2/21. Effective arrivals=28(1−P₁₀)=25.3333/hour. Mean occupancy L=5.2381; mean turnaround 60L/λeff=12.406 minutes. | Staffing illustration for POS/mobile orders. P₁₀ is blocking at capacity; abandonment after joining is outside this model. |
| Order lifecycle | Four transient states (held, queued, brewing, ready); three terminal outcomes (completed, voided, refunded). For transient block Q and exit block R in the runners, N=(I−Q)⁻¹ and B=NR. The queued row sum of N gives 3.1333 expected active steps. The full matrices appear in the evidence. | Transition records can inform the lab. The scenario treats completion as absorbing; the application also permits a later cash refund. Model steps are not elapsed minutes. |
| FAIR-style cash loss | Draw annual event count from rounded Beta-PERT(2,12,45), then per-event loss in PHP from Lognormal(6.2,0.8). Sum losses in each of 100,000 independent simulated years. Python mean annual loss ₱10,723.86, 95th percentile ₱21,378.83. With assumed 78% prevention and ₱3,500 control cost, ROSI=(0.78×ALE−3500)/3500=138.99%. | Scenario for blind drawer reconciliation. Effectiveness and frequency are assumptions, not measured control outcomes. |
| Inspection game | Cashier gain G=500, penalty F=2500, audit cost C=150 and loss L=500. Indifference gives audit probability G/(G+F)=1/6 and fraud probability C/L=0.30. The Python linear program returned 0.1667. | Probability informs the POS spot-audit prompt. It assumes risk-neutral actors and fixed payoffs; it is not an observed fraud rate. |
| PIN entropy and lockout | Assuming uniform four-digit PINs, S=10⁴, H=log₂S=13.2877 bits. At 30 distinct guesses/minute the midpoint estimate is S/(2×30)=166.67 minutes. With three guesses and five minutes of lockout per cycle, effective rate is 3/(5+3/30) guesses/minute, giving 5.90 days. | Illustrates the staff PIN policy. Real PIN selection and operational rate controls can alter the outcome. |
| Reliability block diagram | Assume independent component probabilities: terminal .9999, network .991, cloud .999, local fallback .995. Live=.9999×.991×.999=98.991%. Parallel fallback=.9999[1−(1−.991×.999)(1−.995)]=99.985%. With MTBF=2500 and MTTR=.25 in the same units, inherent availability=2500/2500.25=99.99%. | Models enrolled cash registers with offline fallback. Common failures, expired preparation and reconciliation delays limit the inference. |

### Reproduction and comparison

Work on separate copies of each runner because both write `qmodsim_results.json` beside the script. Run `node run_qmodsim.js` or `python qmodsim_suite.py` from the corresponding copy. Verification used Node 24.14.0 and Python 3.14.2 with NumPy 2.4.1 and SciPy 1.17.0. Python seeds the simulation with 42. JavaScript uses unseeded Math.random; compare deterministic outputs exactly and stochastic outputs statistically.

The six deterministic topics agreed on the shared reported quantities. In the stored result, annual loss was ₱10,749.43 and VaR₉₅ ₱21,296.14. The JavaScript rerun returned ₱10,751.93 and ₱21,387.13, respectively. The Python run returned ₱10,723.86 and ₱21,378.83. The largest mean difference from the stored result was ₱25.57 (0.24%). This comparison measures run-to-run agreement, not empirical validation.
